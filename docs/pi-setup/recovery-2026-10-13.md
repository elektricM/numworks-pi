# Night of 2026-10-13: status and morning steps

## What happened
- The calculator (N0100) was flashed through ROM DFU with a dev firmware that has remote reflash (`SYS:DFU`) and boots straight into the Pi app (`RPI_AUTOSTART`). The Pi booted from it as expected, and HOME still exits the Pi app.
- The Pi's dpkg had been left half-configured by last night's accidental shutdown. I started a repair plus full upgrade in a detached unit.
- That upgrade has two consequences:
  - **`raspberrypi-sys-mods` 20260914 removes `/etc/sudoers.d/010_pi-nopasswd`.** This is an upstream change, and `sudo` now asks for the `pi` password, which I don't have. It stopped me installing anything on the Pi.
    *Correction, later on 2026-10-13: this was wrong. The file is still there (dated December 2025) and passwordless `sudo` works. What made sudo fail that night is unknown, possibly the half-finished upgrade. Step 3 below is unnecessary.*
  - **Kernel 6.18.50** was being installed. The display driver was only built for 6.12. Booting 6.18 without it gives a black calculator screen.
- About 20 minutes into the upgrade, the Pi dropped off the network and did not come back over the next 30+ minutes. The cause is unknown: Wi-Fi, ZeroTier and NetworkManager packages were among those being upgraded. The upgrade was probably interrupted again.

## Morning steps
1. Power-cycle the Pi: hold the calculator's reset, or leave and re-enter the Pi app. Then SSH in.
2. Finish the upgrade:
   ```bash
   sudo dpkg --configure -a && sudo apt-get -f install && sudo apt-get full-upgrade
   ```
3. Optional, your call: give `pi` passwordless sudo back so I can keep iterating unattended. Upstream removed it on purpose.
   ```bash
   echo 'pi ALL=(ALL) NOPASSWD: ALL' | sudo tee /etc/sudoers.d/010_pi-nopasswd && sudo chmod 440 /etc/sudoers.d/010_pi-nopasswd
   ```
4. From the Mac, copy the new code over:
   ```bash
   rsync -a ~/projects/Numworks/hardware/numworks-pi/pi-linux/ pi@nwpi.local:numworks-pi/pi-linux/
   ```
5. On the Pi, install the driver (with DKMS, for every installed kernel), nwpid and nwpi-ctl, then reboot:
   ```bash
   sudo ~/numworks-pi/pi-linux/scripts/install-components.sh && sudo reboot
   ```
6. Check `uname -r`, that the screen comes up, then `nwpi-ctl stat` (no sudo needed).

From then on, `tools/reflash-n0100.sh` on the Mac flashes the calculator with no button presses. It only ever matches the N0100, never the N0110.
